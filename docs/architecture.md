# Architecture and tradeoffs

Ablatrix is a single local Node process serving a React UI and JSON API. SQLite stores runs, experiment queues, optimization records, and cache entries. The browser reads persisted state on load and polls while jobs run. The process listens on `127.0.0.1`; there is no remote account or multi-user authorization layer.

The built-in research definition in `sapiom-agent/index.ts` uses checked source URLs, an optional search hypothesis, and a structured answer with exact quotes from checked excerpts. The quote check establishes provenance within the captured excerpt, not semantic correctness. Fixture mode uses deterministic synthetic output and is marked throughout the UI and exports. Live direct runs are disabled. `server/live-provider.ts` defines the metered-provider contract; tests inject a fake provider to exercise paid-call orchestration. The production provider reports an explicit blocked reason until settled charges and a remote cap can be verified. SQLite reserves capacity across research and proposal calls, records unknown attempts, and stops further dispatch after missing or over-bound evidence. See [the Sapiom accounting boundary](sapiom-accounting.md).

The active evaluation suite has six model-drafted official-source tasks, split by entity and source into development, validation, and a sealed holdout. No independent human label review has occurred. The public API exposes only development and validation prompts, without expected answers. The deterministic rubric is a narrow proxy: required terms, approved source host, and consistent citations. It does not verify every claim semantically. After an optimization is frozen, a one-time paired baseline/candidate fixture holdout assessment can run, persist, and resume after interruption; its results are not passed to the modifier. The optimizer proposes one allowlisted settings change and rejects any regression on a baseline-correct task. It reports no improvement for fixture or unpriced data.

Exports include baseline and candidate configurations, a patch against `configs/research.json`, task-suite checksum, run metadata, and source URLs. They omit credentials. Candidate JSON can be loaded by `npm run replay` for a synthetic fixture run. A live run cannot be reproduced exactly because web content changes and source snapshots are not captured; the manifest records provider metadata only when returned by the metered adapter. Candidate downloads are labeled unvalidated unless the challenger accepted them.

The local app trusts its user. Keep `.env` and the SQLite database private; both may contain inputs or provider metadata. The server binds to loopback, requires same-origin JSON mutations, caps request body size, validates structured input, restricts live scrape URLs to the curated suite, and avoids returning raw provider errors. SQLite schema creation adds the budget ledger to older databases; the app is designed for one local process against its database. A future schema change will require a versioned migration.
