# Sapiom accounting boundary

The installed `@sapiom/tools@0.38.0` `agents.run` contract returns execution ID, status, output, and error. It does not return a dollar charge or the pinned build ID. The [Sapiom run inspector guide](https://docs.sapiom.ai/guides/inspect/) says run-grain metered usage and settled overage are separate dashboard reads; the execution audit is cost-agnostic. It also says there is no per-step, subtree, or build dollar attribution. The [Router API reference](https://docs.sapiom.ai/router/) documents chat response format and activity inspection but does not provide an Ablatrix-verifiable whole-request dollar charge and hard per-request spend bound. The [production-run guide](https://docs.sapiom.ai/guides/run-in-production/) confirms that successful start is only an enqueue event and capability calls add usage.

Consequently, setting `SAPIOM_BUDGET_ENFORCED=1` or an environment variable with a numeric cap cannot establish that Sapiom will enforce that cap, and token counts cannot safely be converted to dollars without verified prices and all capability charges. The production provider reports `ready: false` and never dispatches. The old `runSapiom` and Router functions remain as unmetered adapters for future connection; no application route invokes them while accounting is missing.

The app now has an injected metered-provider contract for local tests. A provider must supply a verified remote-cap reference, an approved total cap, a maximum whole-call charge before each research/proposal dispatch, and settled whole-call charge evidence afterward. The SQLite ledger reserves capacity atomically before dispatch, tracks proposal and research calls together, counts retries and failed calls, settles idempotently, and holds unknown or over-bound calls across restart. A local reservation prevents additional app dispatch but does not itself limit a call already running remotely. Local Cancel stops future tasks; it is not a remote cancellation. A timeout leaves its reservation unknown until independent charge evidence reconciles it.

To connect production safely, obtain an authenticated supported API or explicit provider contract for (1) agent-run total charge including search, scrape, runtime and retries, keyed by execution ID; (2) Router request total charge keyed by request ID; (3) settlement state after failures/timeouts; (4) an enforceable organization or project spending rule covering both surfaces; and (5) a trustworthy upper bound per call or another way to reserve worst-case spend. Verify the deployed ready build identity separately. If any item is unavailable, keep the production gate closed, use the fixture/mocked path, and inspect Sapiom dashboard charges manually without asserting a cost-saving win.

The database has one owning process at a time. Each paid reservation records its experiment or optimization owner before dispatch. An interrupted live experiment remains blocked even after manual ledger settlement until a verified provider reconciliation and resume procedure is implemented; do not edit SQLite directly to bypass this gate. The current ledger uses whole cents, so sub-cent provider charges require a unit migration before production use.
